# Photo Frame Test Dataset

> Current checkpoint: `v0.10.67`. This README was refreshed in the docs/launcher reconciliation pass; code, focused tests, proof artifacts, and runtime evidence override stale prose.

Generated by `generate_photo_frame_test_dataset.py`.

## What this dataset covers

- **gps_valid/**: happy-path JPEG images with valid EXIF GPS
- **gps_same_location/**: multiple JPEGs with the same GPS for cache / dedup tests
- **no_gps/**: JPEGs with no GPS metadata
- **invalid_gps/**: JPEGs containing intentionally invalid GPS coordinates
- **rotated/**: JPEGs with EXIF orientation flags for slideshow rendering tests
- **duplicates/**: byte-for-byte duplicate copies of valid JPEGs
- **corrupted/**: broken/truncated/random-byte files to test parser failure paths
- **heic/**: optional HEIC generation outputs or explanatory placeholders
- **videos_with_gps/**: optional MP4 videos with best-effort generic location metadata
- **videos_no_gps/**: optional MP4 videos with no location metadata
- **mixed_batch/**: representative mix for end-to-end pipeline tests

## Recommended uses

1. Run a **small mixed-batch** end-to-end flow first.
2. Run **full indexing** on the entire dataset.
3. Validate:
   - GPS parse success/failure separation
   - geocode cache reuse for same coordinates
   - no-GPS terminal behavior
   - retry/backoff handling for corrupted or invalid files
   - slideshow handling for rotated images and videos

### Video fixture source, permission, and privacy

- **Source / ownership:** These clips were synthetically generated for this dataset and are intended for deterministic local proof use.
- **Permission/license:** These fixtures may be committed to this repository/dataset ZIP and used for local automated or manual proof runs for this project.
- **Privacy/safety:** The clips contain no private faces, addresses, license plates, account data, or real private media. GPS values are synthetic metadata labels for parser tests.
- **Proof-only boundary:** These files are not production media and must not be used to claim real iPhone capture, iCloud download, Raspberry playback, monitor pixel correctness, or reboot recovery.
- **Expected behavior:** Valid GPS videos should be recognized as video media with location metadata when the parser supports QuickTime/MP4 location tags. No-GPS videos should stay in the no-location path. Invalid videos should be rejected gracefully without crashes or fabricated metadata.
