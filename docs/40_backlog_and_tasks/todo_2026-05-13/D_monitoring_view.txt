1. Task Understanding

View D is intended to be a live runtime monitor for the current pipeline, playback worker, and screen worker. The immediate goal is to verify what is actually live today, classify mock/stale/partial/real surfaces, then plan the smallest path to make the page honest and useful.

No code was changed.

2. Verified Current-State Summary

View D is rendered by dashboard/views/runningProcessView.ts and selected from dashboard/app.ts. Entering View D triggers runAction('refresh-running-process') at dashboard/app.ts.

There are two View D paths:

- start-real-run is local simulation only: dashboard/services/runtimeTruth/runtimeTruthDemoActions.ts.
- refresh-running-process calls backend GET /api/runtime/projection/live: dashboard/services/runtimeTruth/runtimeTruthBehavior.ts, dashboard/services/runtimeExecutionService.ts.

The backend route exists at server/index.ts, but its worker/playback/screen fields are mostly hardcoded unknown/null: server/index.ts.

The playback worker is the only backend scheduler CLI worker implemented: server/index.ts. It writes runtime_data/scheduler/playback-worker-status.json: server/workers/playbackWorker.ts.

regular_stage_worker.ps1 and screen_on_off_worker.ps1 exist, but run through CronEmulator PowerShell HTTP calls. Screen is simulation-only, not real hardware control.

Current runtime evidence checked: runtime_data/scheduler contains selected-target.json only; no playback worker status, host status, or heartbeat files were observed. tools/CronEmulator/crontab_emulated.txt is currently missing.

5. Implementation Plan To Make It Work

Stage 1: make truth visible without changing workers.
Fix View D so “Live monitor active” depends on backend projection.runState.value or explicit monitor availability, not merely the presence of a projection object. Show unknown/unavailable honestly.

Stage 2: wire frontend to existing backend projection cleanly.
Preserve GET /api/runtime/projection/live; map source labels into visible/inspectable UI. Add inspect metadata for refresh-running-process.

Stage 3: make backend projection read existing authoritative artifacts.
Start with existing artifacts only: orchestration state, playback-worker-status.json, playback DB state, scheduler selected target, host status if present. Do not invent regular/screen worker status files until those workers actually produce them.

Stage 4: add focused tests.
Add route test for /api/runtime/projection/live, frontend action test for refresh-running-process, and artifact-mapping tests for playback worker status.

Stage 5: reconcile docs/status metadata.
Update View D status docs and placeholder_implementations.md from “mock-only/no backend” to “partial backend projection; worker artifact ingestion incomplete.”
